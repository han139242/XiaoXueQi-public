# 羽毛球 MES 系统后端接口文档（最终版）

项目根路径：`http://localhost:8088`

本文档用于指导羽毛球 MES 系统后端接口设计和前后端联调。本文档综合三份小组接口文档整理形成：保留完整的后端模块覆盖和 Controller/Service/Mapper 设计清单，吸收通用状态码、常用状态值、最小业务闭环、`/full` 主从表提交接口和开发注意事项。

接口格式参考老师给出的文档写法：每个模块说明统一路径，每个接口说明请求路径、请求参数、请求方式和返回数据格式。

后端建议统一采用：

```text
Controller：接收前端请求，定义接口路径
Service：处理业务逻辑
Mapper：操作数据库
Entity：对应数据库表
```

统一返回格式：

```json
{
    "msg": "操作成功",
    "code": 200,
    "data": {}
}
```

通用状态码：

```text
200: 操作成功
400: 参数错误
401: 未登录或 token 无效
403: 无权限访问
404: 数据不存在
500: 操作失败
1001: 用户名或密码错误
1002: token 过期或无效
1003: 业务处理异常
```

分页返回格式：

```json
{
    "msg": "操作成功",
    "code": 200,
    "data": {
        "records": [],
        "total": 0,
        "size": 10,
        "current": 1,
        "pages": 0
    }
}
```

接口路径约定：

```text
/api/auth      认证接口
/api/sys       系统管理接口
/api/org       组织人事接口
/api/mdm       主数据管理接口
/api/process   工艺管理接口
/api/factory   工厂建模接口
/api/mfg       生产制造接口
/api/wms       仓储库存接口
/api/qms       质量管理接口
/api/eam       设备管理接口
/api/trace     条码追溯接口
/api/dashboard 首页看板接口
```

最终统一规则：

```text
接口前缀统一使用 /api
分页查询统一使用 /page
分页参数统一使用 current、size
分页返回统一使用 records、total、size、current、pages
删除接口统一做软删除，不做物理删除
状态字段统一使用英文枚举值，前端通过字典显示中文
主表和明细一起提交时，统一增加 /full 接口
```

登录后访问需要认证的接口时，请在请求头中携带 token：

```text
Authorization: Bearer token值
```

## 通用管理接口模板

除登录、看板统计和业务流转接口外，本文档中的管理类模块默认都提供以下接口。后端开发时每个资源对应一个 Controller、Service、ServiceImpl、Mapper。

### 查询分页列表

1. 请求路径：`/page`
2. 请求参数：

```text
current: 当前页码，默认 1
size: 每页显示条数，默认 10
keyword: 关键字，可选
status: 状态，可选
beginTime: 开始时间，可选
endTime: 结束时间，可选
```

3. 请求方式：`get`
4. 返回数据格式：

```json
{
    "msg": "操作成功",
    "code": 200,
    "data": {
        "records": [
            {
                "id": 1,
                "code": "CODE001",
                "name": "示例数据",
                "status": "ENABLE",
                "remark": "备注"
            }
        ],
        "total": 1,
        "size": 10,
        "current": 1,
        "pages": 1
    }
}
```

### 根据ID查询详情

### 主从表一次提交

主从表一次提交用于处理一张主表和多条明细同时保存的业务。后端实现时必须加事务，主表或任意明细保存失败时全部回滚。

适用模块：

```text
BOM + BOM明细
工艺路线 + 工艺路线明细
入库单 + 入库明细
出库单 + 出库明细
退料单 + 退料明细
盘点单 + 盘点明细
生产报工 + 报工用料
检验单 + 检验结果
不合格品处理单 + 处理明细
```

## 后端落地前检查项

根据当前仓库中的 Entity 初步检查，部分关联表或明细表实体存在 `id` 字段，但 `@TableId` 暂时标在了业务关联字段上。正式生成 Mapper、Service、Controller 前，需要先校正这些实体，否则 MyBatis-Plus 的 `getById`、`updateById`、`removeById` 可能按错误字段执行。

需要重点检查：

```text
SysUserRole: 当前应优先确认 id / userId 的主键映射
SysRoleMenu: 当前应优先确认 id / roleId 的主键映射
OrgTeamMember: 当前应优先确认 id / teamId 的主键映射
FactoryStationOperation: 当前应优先确认 id / stationId 的主键映射
MfgTaskOperator: 当前应优先确认 id / taskId 的主键映射
QmsInspectionSchemeItem: 当前应优先确认 id / schemeId 的主键映射
```

建议处理方式：

```text
如果数据库表存在 id 主键，则 Entity 的 @TableId 应标注在 id 字段上。
如果数据库表使用复合唯一约束作为业务唯一性，也仍建议保留单一 id 主键，业务字段通过唯一索引约束。
```

## 开发注意事项

1. 删除接口统一做软删除，只修改 `deletedFlag`，不要物理删除生产、质量、库存、追溯数据。
2. 所有分页接口统一使用 `/page`、`current`、`size`，返回 `records`、`total`、`size`、`current`、`pages`。
3. 所有接口路径统一增加 `/api` 前缀，不再使用 `/user`、`/mfg/work-order` 这类无前缀路径。
4. 生产订单、生产计划、生产工单、生产任务、入库单、出库单、检验单都必须有状态流转。
5. 关键状态变化要写入 `sys_status_change_log`，关键操作要写入 `sys_operation_log`。
6. 入库和出库必须同时更新库存余额 `wms_inventory`，并写入库存流水 `wms_stock_movement`。
7. 库存数量不能通过普通修改接口直接手改，必须通过入库、出库、退料、盘点等业务动作变更。
8. 报工时必须保存合格数量、不良数量、实际工时和物料消耗。
9. 质检结果不合格时，可以生成不合格品处理单，处理方式包括返工、报废、降级和让步接收。
10. 安灯告警、生产异常、设备维修是联动关系，但不要混成一个接口或一张表。
11. 采购批次使用 `wms_material_batch`，生产批次使用 `trace_product_lot`，两类批次不能混用。
12. 条码追溯通过产品批次、物料批次、报工用料、检验记录串联，不重复保存所有业务数据。
13. 主从表 `/full` 接口必须加事务，任意一步失败时主表和明细全部回滚。
14. 前端展示中文状态，后端和数据库统一保存英文状态值。
15. 后端开发时优先使用已有 `ResultData`、`ResultCode`、MyBatis-Plus、JWT、Redis、Excel 工具，不新增无关依赖。
